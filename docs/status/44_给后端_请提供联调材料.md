# 44 给后端：请提供 Trace 前端联调材料

## 目的

前端需要接入两类已经由引擎计算的结果：

1. **Ask 问答与证据**：所有问题必须交给引擎，前端不直接调用 LLM，也不自行计算数量或尺寸。
2. **2.5D 场景**：由 IFC、矢量 PDF 或扫描图识别出的房间、墙、门窗、构件和机电路径；前端只负责显示和交互。

请提供下面列出的材料。密钥只放本地 `.env` 或部署环境，**不要**发到聊天、文档或 Git。

---

请一次性回复以下内容：

```text
1. 本地后端 Base URL：例如 http://localhost:8765

7. 已知限制、失败模式与还未实现的字段
```

## B. Ask 与证据接口（最高优先级）

### 1. 单张图纸问答

```http
POST /ask
Content-Type: application/json

{
  "path": "data/.../drawing.pdf",
  "page": 1,
  "question": "How many doors are on this floor?"
}
```

对于上传文件，也可接受：

```json
{"id": "<document-id>", "question": "How many doors are on this floor?"}
```

必须返回（字段可增加，不能改名）：

```json
{
  "answer_id": "stable-answer-id",
  "value": 12,
  "unit": "count",
  "confidence": "high",
  "confidence_reason": "why this confidence is appropriate",
  "warnings": [],
  "alternatives": [],
  "items": [
    {
      "id": "stable-item-id",
      "box_norm1000": [100, 200, 130, 240],
      "guid": null
    }
  ],
  "method": "engine method actually used",
  "sources": [{"file": "data/.../drawing.pdf", "page": 1}]
}
```

规则：

- `value: null` 表示该图纸不能回答，不是 0；必须说明原因到 `warnings`。
- `confidence` 仅可为 `high / medium / low / none`。
- 每条 warning 都要原样返回给前端，尤其是“这是 site plan，不适合回答楼层门数量”或“未标定，不能实量”。
- 计数 / 面积 / 长度等数值只能来自引擎工具；前端和 LLM 都不能补算或猜测。
- `items` 内应尽量给可定位几何：`box`（PDF point）、`box_norm1000`、`polygon`、`polygon_norm1000` 或 IFC `guid`。

### 2. 多图纸项目问答

```http
POST /docs                 multipart: file, project, building
GET  /project/sheets?project=<project>
POST /project/ask
Content-Type: application/json

{"project": "<project>", "question": "How many doors are on the first floor?"}
```

请提供以下可工作的演示：

- 上传至少三张 sheet：site plan、floor plan、door schedule。
- `GET /project/sheets` 返回 sheet number、discipline、level、kind（site plan / floor plan / schedule）。
- 对“first floor doors”的项目问题，引擎选择 floor plan 或 door schedule，**不选择 site plan**。
- 响应中的 `items` 至少标明每张采用的 sheet 及其 `answer_id`；提供 `evidence.rule` 解释选图原因。

### 3. 证据接口

```http
GET /evidence?answer_id=<id>
GET /evidence?answer_id=<id>&view=zoom
GET /evidence?answer_id=<id>&view=full
```

请保证：

- JSON 包含 `locations`，每个位置有 `page`、`bbox_norm1000`，有 PDF 坐标时也可带 `bbox_pt`。
- `view=zoom` 和 `view=full` 返回 PNG；其上有问题、答案、置信度、来源文件 / 页码及编号证据框。
- 同一 `answer_id` 在前端会话期间可重复查询，不能立即失效。

### 4. 复核和测量（若当前已完成）

```http
POST /review
POST /calibrate
POST /measure
```

请附上每个接口的最小成功请求与响应；尚未实现请明确标记 `not ready`，不要返回伪结果。

## C. 2.5D 几何场景接口

**不能使用或覆盖**已有 `GET /api/scene`：它是多人家具摆放状态。

请单独提供：

```http
GET /api/geometry/scene?path=<source-path>&page=<optional-page>
```

后端按文件类型调用已有 `scene_ifc / scene_pdf / scene_scan`，将引擎 JSON 原样透传；不在路由中重新识别、计数或编造对象。

### 必需字段

```json
{
  "project_id": "stable-project-id",
  "source_kind": "ifc | pdf_vector | scan",
  "quality": "measured | illustrative",
  "unit": "m | norm1000 | px",
  "coordinate_system": "declared source coordinates",
  "plan_up_vector": [0, -1],
  "warnings": [],
  "storeys": [],
  "rooms": [],
  "walls": [],
  "openings": [],
  "objects": [],
  "systems": []
}
```

每个输出元素尽量提供：

- 稳定 `id`（IFC 优先用 GUID）、`storey_id` / `room_id`；
- `source.file`、`source.page` 和 `source.bbox_norm1000` 或 `source.bbox`；
- 实际 `method`、`confidence: 0..1`、`assumed`；
- 墙、房间、门窗、WC、sink 的真实平面位置、方向和比例；
- 有可靠路径时才输出 `systems`（water / drain / electrical / hvac）。

质量规则：

- `quality: measured` 只用于 IFC、已标定扫描图或有可靠比例的矢量图；`unit` 必须为 `m`。
- 未标定扫描图必须是 `illustrative`，使用 `norm1000` 或 `px`；不能给伪精确的米制面积或尺寸。
- 矢量平面图没有立面信息时，`wall.height_m` / `opening.height_m` 可以为 `null`。前端只将其作为带标记的视觉默认高度，绝不会展示成实测值。
- 未标定扫描图的门窗可缺 `rotation_deg`、`width_m`、`height_m`；前端只显示相对示意。
- `source.bbox_norm1000` 原样返回即可，前端会按实际加载的 PNG 尺寸换算证据框。

### 请提供的三份最小样例

1. IFC 实量：Duplex 的一个卫生间；含房间、墙、门窗、至少一个 WC 或 sink。
2. 矢量 PDF 实量：School 一层；含房间与门窗。
3. 扫描图示意：School 或 CubiCasa 一页；明确 `illustrative`。

每份场景都请先在仓库根目录通过：

```powershell
node scripts/check_geometry_scene.mjs <scene.json>
```

## D. 交付格式与验收

请将以下材料发回：

1. 本地启动步骤（无 key）。
2. 可复制的 curl / PowerShell 请求，分别覆盖 `/ask`、`/evidence`、`/project/ask`、`/api/geometry/scene`。
3. 三类输入文件的安全路径或上传步骤、实际响应 JSON、对应 evidence PNG。
4. 失败时的 HTTP 状态码和 JSON 错误格式。
5. 已知未完成事项清单。

前端验收条件：

- 不会把 site plan 当作 floor plan 回答；不适用的问题会显示低置信度和 warning。
- 答案卡显示 value、unit、confidence、reason、warnings、alternatives 和 evidence。
- 点击证据能定位到原图正确页和正确区域。
- 2.5D 中房间、墙、门窗和卫生构件与原图相对位置相符。
- 未标定扫描图始终明确显示为示意，不能出现“实量”或米制比例尺。
- `/api/scene` 协作功能保持正常。
