# 45 给后端：仅做 2.5D 几何场景路由更名

## 已确认

- 现有 `GET /scene?model=&since_version=` 是 Trace 的**家具协作摆放状态**：读取和保存家具位置、版本与历史。
- 这个接口和 `POST /scene/placement`、`DELETE /scene/placement`、`GET /scene/history` 必须完整保留。
- 2.5D 几何场景（IFC / PDF / scan 的 rooms、walls、openings、objects、systems）是另一类数据，不能复用或覆盖上述协作接口。

## 请改的唯一接口

将目前几何场景的 GET 路由：

```text
/scene
/api/scene
```

改为仅：

```text
GET /api/geometry/scene?path=<relative-data-or-upload-path>&page=<optional-page>&storey=<optional>&room=<optional>&space_model=<optional>
```

路由内部仍然按原有逻辑调用：

- IFC → `scene_ifc.scene(...)`
- 矢量 PDF → `scene_pdf.scene(...)`
- 扫描 PDF / image → `scene_scan.scene(...)`

只改路由名称与挂载位置；不要改识别、计数、坐标或 JSON 字段。

## 验收

以下两个请求必须返回不同类型的数据，并且都正常：

```text
GET /scene?model=data/ifc_models/sample_building.ifc
→ {"model": "...", "version": 0, "placements": []}

GET /api/geometry/scene?path=data/.../model.ifc&room=Bathroom%201
→ {"project_id": "...", "quality": "measured", "rooms": [...], "walls": [...], ...}
```

`/api/geometry/scene` 失败时使用既有 JSON 错误格式；不能影响家具协作接口。
