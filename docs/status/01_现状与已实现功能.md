分支 `claude/night`。已推送到 GitHub 组织仓库 `TRACE-Montree/Trace`，CRACI CI 第一次运行通过。标“已实测”的是在本机网页上亲眼看过结果；其余只是代码合入、测试通过。

## 准确率（评分 25%）

**离线抽样评测**：每个来源随机抽 50 题，只调用 engine，不联网。详见 `docs/eval-results.md`。

| 来源 | 正确 | 带框 |
| --- | --- | --- |
| swiss_dwellings | 49/50 (98%) | 98% |
| ifc_models | 46/50 (92%) | 16% |
| cubicasa5k | 2/50 (4%) | 2% |

- **cubicasa** 实际答题时 engine 没有结果，会自动转去用 Gemini 视觉计数，再用 Nemotron 复核；离线评测没算这一路，所以 4% 偏低。真实准确率还没有系统评测过。
- **ifc 4 题错**：3 题是楼层或房间净面积偏大 7–8%（molio 模型），1 题“梁数量”engine 没返回值。
- **swiss 1 题错**：apartment A 面积把不该算的房间算进去了。

**已实测**：
- swiss 窗 13 个，门 21 个，都和标准答案一致，图上每个都有编号框。
- IFC 卫生间面积 4.35 m²，和标准答案一致。

## 智能体 / 后端（agent/）

- FastAPI `/ask`：Gemini 3.8 Flash，temperature 0，工具调用最多 5 步。优先调 `answer_from_engine`，也就是 Xinran 的 `engine.answer`。
- **数字校验**：答案里出现的每个数字都必须来自工具返回。
- **工具**：`room_status`、`sum_values`（求和交给代码算）、`scan_drawing_inventory`（全图构件识别并按类别编号）、`count_in_drawing`（视觉计数）。
- **Nemotron 3.5 Super VL**：部署在 Verda 容器上，用来复核栅格图的计数，结果显示为绿/黄徽章，并和 engine 并行跑。
- **IFC 答案也能在 2D 图上画框**：通过 SVG 里的 `data-guid` 对应过去。
- **缓存**：视觉调用缓存和 `/ask` 答案缓存都存磁盘，加 `?fresh=true` 可以跳过。
- **返回字段**：每个答案带 `trace`（推理步骤）、`usage`（token 数和调用次数）、`timing`（耗时）。目前只是后端返回，前端面板还没做。
- **角色**：Architect / Electrician / Plumber / Owner，会改变回答的侧重点。
- **其他接口**：`/render` 用 Gemini 图像模型生成氛围效果图；`/collab*` 是社区协作的接口。
- **测试**：pytest 41 个全部通过。

## 网页（web/）

- **首页**：按 Gigi 的设计稿和配色做的落地页，导航为 Home / Ask / Community。
- **Ask 页**：
  - 可以选数据集样例题，也有 5 个 Demo 场景，能自由提问，能切换角色。
  - 2D 图纸可以适应屏幕、缩放和拖动；橙色框带编号，点编号能定位到对应构件。
  - 有“Scan & number all elements”（全图构件识别编号）。
  - 有建筑层级树：楼层 → 房间 → 构件，点击可以定位。
- **3D 页**：
  - 按 GUID 高亮构件；摆放家具（Demo 目录，按真实尺寸）。
  - 截图可以加备注，能生成氛围效果图，能导出 BOM 清单（CSV）。
  - 刚合入了楼层剖切和工种图层（建筑 / 结构 / 给排水 / 电气 / 家具），但有 bug，见下文。
- **Community 页**：第一次进入时登记联系方式；有房间聊天、私聊，以及精确到小时的施工时间线。时间冲突时通知双方，先预约的人保留时段，并显示双方联系方式。“业主透明度设置”是否已经做完待确认。
